# NCC 使用 LiDAR 深度选择参考图像（2026-09-17）

## 原因与修改范围

parking01_section 的旧日志只有 76/863 张训练图像通过“共享 SfM 点 >=50”筛选，
多数 NCC 步直接因 `source=-1` 返回 0。新方案不使用 SfM 的特征轨迹，只使用已有相机
内外参和 LiDAR 深度。相机位姿及 LiDAR/图像配准仍须可靠。

- `examples/ncc_view_selection.py`：独立选图、深度重叠、JSON 缓存。
- `examples/ncc_loss.py`：移除旧共视轨迹函数，调用新选图函数；每次从候选中随机取一张。
- 不修改训练入口、MCMC、KNN、noise、损失权重及 NCC patch/反向传播。

## 具体过程

1. 在当前训练集内按相机距离从近到远取最多 20 个候选；基线 0.05–30 m，
   朝向夹角不超过 75 度。这三个几何条件与旧版一致，不以共享特征数量筛选。
2. 复用 `Dataset(..., load_depths=True)`，每张图只加载一次用于建表。深度与 mask
   按整数步长抽样，最长边 <=320，内参按同一步长缩放。避免混合前后景深度。
3. 在每张参考图的有效低分辨率深度上均匀抽取最多 2048 个点，反投影到世界坐标。
4. 向候选图投影，检查正深度、图像范围、mask 与深度一致性：
   `abs(z_projected - depth_source) <= max(0.15 m, 0.02*z_projected)`。
   这里取最近深度样本，训练中的原有双线性 patch/遮挡检查仍然保留。
5. 用通过点数 / 参考有效采样点数作为有向重叠率；只保留 >=10% 的候选，
   按重叠率取最多 5 张。没有合格候选就跳过，不人为补入不可靠视角。
6. 训练的每个 NCC 事件随机使用其中一张，不增加每步渲染的参考图数量。

LiDAR 仅用于选图。NCC 仍通过 **当前渲染深度 -> 平面 warp -> patch NCC**
回传梯度到 GS；不把渲染深度替换成固定 GT。纯色区域仍可能因无纹理而被 patch 筛掉。

## 缓存与使用

保持原训练命令的 `--ncc-loss`，无需新参数或 CUDA 编译。
第一次初始化生成 `<data_dir>/ncc_source_views.json`，保存图像名称和重叠率，
不保存新的 RGB/深度图。后续初始化命中缓存时无需再读取图像和深度。

缓存签名覆盖训练图像顺序、位姿、内参、畸变参数、data factor、选图参数，
以及图像/深度/mask 文件的路径、大小和修改时间；这些变化会触发重建。
只改学习率、GS 模型或 max_steps 不重建。多进程通过临时文件原子替换缓存，
但首次同时启动多个进程仍可能重复建表。

相机 pose 优化期间选图表不逐步更新；训练期 warp 仍使用当前 pose。
大幅位姿改变需要重新建表。修改深度解码等预处理逻辑时须递增缓存版本或移除该 JSON。

重叠只是候选资格，不保证每次都有有效 NCC patch。日志 `source=-1` 表示无候选；
`source>=0, patches=0` 表示后续纹理、平面拟合或遮挡筛选未通过。
覆盖率增加后实际 NCC 计算次数也会增加；不能以旧版大量跳过时的耗时作为同等工作量比较。

## 验证

测试包含遮挡/无效深度排除、相机几何筛选、深度抽样与内参一致性、非连续训练索引、
无 SfM 轨迹的建表、缓存复用与失效、无有效参考时不强行配对。
原 NCC 几何扰动、遮挡与渲染深度到 GS 的梯度回归继续保留。

服务器实测（parking01_section，863 张训练图像）：

- 新选图覆盖 863/863 张，每张都有 5 个通过筛选的候选；旧方式为 76/863。
- 每张图最佳候选重叠率：最低 54.0%，中位数 87.7%，最高 99.4%。
- 本次 CPU 建表加 Parser 初始化约 20.4 秒；缓存校验/读取约 0.05 秒，JSON 约 391 KiB。
- 48 项 CPU/CUDA 回归通过。实测缓存只写到测试临时目录；实际训练首次启动会自行生成缓存。
- 额外抽查 5 张真实图像，以 LiDAR 深度作为几何输入（不是训练模型渲染），
  全部得到有效 NCC patch，数量为 33、48、18、167、17；用于检查选图与 patch 调用衔接。

这些结果验证选图覆盖率和程序回归，不等同于完成场景训练或证明 NVS 指标提升。
