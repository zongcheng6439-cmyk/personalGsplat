# NCC 平面 warp 等价重构（2026-09-17）

## 范围

只整理 `examples/ncc_loss.py` 的重复计算，不切换成逐像素深度 warp。
LiDAR 候选选图、5x5 patch、11x11 PCA 平面拟合、法向停止梯度、平面距离的梯度、
深度边界、alpha、mask、平面质量、纹理、遮挡检查及所有阈值均保持不变。
训练入口、损失权重、MCMC 和训练 shell 不修改。

## 合并投影

令 `r = inverse(K_ref) * pixel`，局部平面为 `n dot X = d`，
两视角相对变换为 `(R,t)`。原单应变换作用于像素，等价于：

```
rotated = R * r
q = K_src * (rotated + t * (n dot r) / d)
source_xy = q.xy / q.z
source_depth = rotated.z * d / (n dot r) + t.z
```

新 `_project_plane_patch()` 共用射线、旋转射线和法向点积，一次返回投影位置和深度。
相机内参求逆由每次两次减少为一次，不再为深度检查重复构造完整三维点。
这里的深度仍来自同一个拟合平面，并非各像素原始渲染深度分别投影。

保留原先的带符号小分母保护，以及齐次投影分母的 clamp。没有简单地把它替换成
三维点除以深度，以免在无效/退化射线处改变旧版的数值保护行为。
内参和位姿不跨 step 缓存，避免相机调整或输入改变后使用过期值。

## 固定计算缓存

- `_patch_offsets()` 按窗口大小和设备缓存 5x5、11x11 网格，最多 8 份小张量。
- 源图仍保留原有 uint8 转换，但在原先的 8 张 CPU LRU 缓存里保存归一化灰度。
- 双线性插值与线性 RGB 灰度加权可交换顺序，因此从“采样 RGB 再转灰度”
  改为“缓存灰度并直接采样灰度”。源图颜色采样从 3 通道变为 1 通道。
- 当前输入图像的灰度只算一次，候选筛选与最后 NCC 复用；不跨 step 缓存当前输入，
  避免图像预处理改变时使用旧图。源图灰度失效随原有 LRU 淘汰自动处理。

NCC 仍是 `mean(1-rho)`，不是 PGSR 中其他相关系数变体。
不同浮点运算顺序会带来舍入误差，不承诺逐 bit 一致。

## 验证结果

62 项 CPU/CUDA 测试通过，包含原有回归，以及以下等价性测试：

- float32/float64 投影位置、源深度与距离/法向/相对位姿梯度对比；
- 正负、零及接近零分母的保护行为；
- 灰度转换与双线性采样交换顺序后的值和梯度；
- 完整 NCC 的 patch 数、损失和深度梯度；
- 原有渲染深度到 GS 位置的反向传播。

另用 parking01_section 的 5 张真实图像和 LiDAR 深度作为测试输入，对比旧/新实现。
固定随机种子后参考视角与有效 patch 数完全相同（33、28、100、132、58）：

- loss 最大绝对差约 `9.54e-7`；
- 深度梯度最大绝对差约 `1.36e-6`。

这不是重新训练的 NVS 对比，也没有声称整个训练固定加速多少。
接近筛选阈值的输入仍可能受浮点舍入影响；没有修改任何阈值或有意扩大/缩小有效集合。
